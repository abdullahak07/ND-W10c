CLOUD COMPUTING

What makes a cloud a cloud?

NIST describes cloud computing as on-demand network access to a shared pool of configurable resources that can be rapidly provisioned and released with minimal management effort.

01Broad network accessUse services over standard networks from many device types.
02Rapid elasticityScale resources up or down as demand changes.
03Measured serviceUsage is metered, monitored and reported.
04On-demand self-serviceProvision resources without waiting for provider staff.
05Resource poolingShared infrastructure serves many consumers dynamically.
Easy example:Cloud is like electricity: you use what you need, when you need it, without owning the whole power station.

02
SERVICE MODELS

SaaS, PaaS and IaaS = different control boundaries.

The deeper you move from SaaS toward IaaS, the more control the customer gains — and the more configuration and security responsibility the customer keeps.

SaaSUse the application

Provider runs the application and cloud infrastructure. Customer mainly uses the service through a browser or client.

Examples in the lecture: Gmail, Microsoft 365, Salesforce, WebEx.
PaaSBuild on the platform

Provider supplies runtimes, development tools and platform services so customer applications can run.

Think: “operating system in the cloud.”
IaaSControl the virtual machines

Customer controls operating systems and deployed applications while the provider manages the underlying infrastructure.

Examples: EC2, Azure, Google Compute Engine.

DEPLOYMENT MODELS

Where does the cloud live, and who shares it?

Public, private, community and hybrid clouds trade cost, control, scale, performance and security differently.

PUBLICShared provider infrastructure

Low cost and high scalability, but security and compliance concerns require careful management.

PRIVATEDedicated to one organisation

Tighter control over data location and security; higher cost and management effort.

COMMUNITYShared by similar organisations

Restricted access for organisations with common requirements, such as regulated sectors.

HYBRIDTwo or more clouds connected

Keep sensitive workloads private while using public-cloud benefits for less sensitive workloads.
